# Система устойчивости к сетевым ошибкам

## Обзор
Реализована комплексная система обработки потери интернет-соединения и сетевых ошибок в booking_bot.py для решения проблемы, когда "после отключения wifi модуля и затем включения поиск продолжился но не было никакого сообщения в телеграм о том что соединение прерывалось".

## Решение проблемы

### ❌ Проблема ДО обновления:
- При отключении Wi-Fi операции Playwright прерывались молча
- Пользователи не получали уведомлений о сетевых проблемах  
- Сессии могли потеряться без возможности восстановления
- Отсутствовала автоматическая обработка сетевых сбоев
- **Воркеры полностью останавливались при сетевых ошибках**

### ✅ Решение ПОСЛЕ обновления:
- **Автоматическое обнаружение** всех типов сетевых ошибок
- **Мгновенные уведомления** пользователей о проблемах с сетью
- **Автоматические повторные попытки** (3 раза с экспоненциальной задержкой)
- **Сохранение сессий** при сетевых сбоях для последующего восстановления
- **Воркеры продолжают работу** - сессии автоматически возвращаются в очередь для повторной обработки

## Обработка различных типов отключений

### 📶 Отключение WiFi модуля
**Когда происходит:** Пользователь отключает WiFi в настройках устройства или физически выключает WiFi адаптер.

**Как система реагирует:**
1. **Мгновенное обнаружение** - ОС сразу знает об отключении
2. **Ошибки типа** `net::ERR_INTERNET_DISCONNECTED`, `WiFi is turned off`
3. **Быстрое уведомление** пользователя (в течение 1-2 секунд)
4. **Сохранение сессии** и переход в режим ожидания

### 🌐 Отключение от сети роутера  
**Когда происходит:** Роутер выключен, кабель отключен, блокировка на уровне роутера/провайдера.

**Как система реагирует:**
1. **Обнаружение по таймауту** - может занять 10-30 секунд
2. **Ошибки типа** `getaddrinfo failed`, `Connection timeout`, `502/503/504`
3. **Уведомление после попыток** (3 попытки с экспоненциальной задержкой)
4. **Автоматические повторы** до восстановления соединения

### 🔧 Единая система обработки
Независимо от типа отключения, система:
- ✅ **Обнаруживает все виды** сетевых проблем
- ✅ **Уведомляет пользователя** с описанием проблемы  
- ✅ **Сохраняет сессию** для восстановления
- ✅ **Автоматически восстанавливает** работу при появлении сети

### 🔍 Сценарий: Пользователь отключает Wi-Fi во время поиска слотов

1. **Обнаружение проблемы** (мгновенно):
   - Playwright генерирует ошибку типа `net::ERR_INTERNET_DISCONNECTED`
   - Система автоматически классифицирует её как сетевую

2. **Первая попытка повтора** (через 10 сек):
   - Логирование: `WARNING - Сетевая ошибка при поиск слотов (попытка 1/3)`
   - Автоматическая повторная попытка операции

3. **Вторая попытка повтора** (через 20 сек):
   - Логирование: `WARNING - Сетевая ошибка при поиск слотов (попытка 2/3)`
   - Ещё одна повторная попытка

4. **Уведомление пользователя** (после 3-й неудачной попытки):
   ```
   🌐 **Проблемы с интернет-соединением**
   
   Воркер #1 обнаружил проблемы с сетью.
   🔄 Система автоматически повторит попытку подключения...
   ```

5. **Сохранение для восстановления**:
   - Сессия пользователя сохраняется в `paused_sessions`
   - Задание возвращается в очередь `task_queue` для повторной обработки
   - Воркер продолжает работу с другими заданиями

6. **Автоматическое восстановление**:
   - При восстановлении сети задание автоматически берется из очереди
   - Система проверяет наличие сохраненной сессии в `paused_sessions`
   - Если сессия найдена - восстанавливается состояние браузера
   - Если нет - создается новая сессия

## Поведение при сетевых ошибках

### В run_booking_session()
1. **NetworkConnectionException**: Сохранение сессии → переход в режим паузы
2. **TemporaryNetworkException**: Сохранение сессии → повтор через время
3. **PlaywrightTimeoutError**: Анализ причины → сохранение при сетевых проблемах

### В book_available_slot()
1. **Загрузка страниц**: retry_network_operation для wait_for_load_state
2. **Клики по элементам**: retry_network_operation для взаимодействий с календарем
3. **Ожидание поиска**: retry_network_operation для длительных операций
4. **Перезагрузка**: retry_network_operation для page.reload()
5. **Выбор слотов**: retry_network_operation для всех этапов бронирования

## Технические детали

### Обнаруживаемые типы сетевых ошибок:

#### 📶 Отключение WiFi модуля (на устройстве):
- `net::ERR_INTERNET_DISCONNECTED` - полное отключение интернета
- `net::ERR_NETWORK_CHANGED` - смена сети (Wi-Fi → мобильная)
- `WiFi is turned off` - WiFi модуль выключен
- `The network adapter is disabled` - сетевой адаптер отключен

#### 🌐 Отключение от сети роутера (физическое/логическое):
- `getaddrinfo failed` - DNS сервер недоступен через роутер
- `Connection timeout` - роутер не отвечает на запросы
- `Connection refused` - роутер отклоняет соединения  
- `No route to host` - роутер не может найти маршрут
- `Host unreachable` - целевой хост недоступен через роутер
- `502 Bad Gateway` - роутер получил неверный ответ от upstream
- `503 Service Unavailable` - роутер перегружен или недоступен
- `504 Gateway Timeout` - роутер не получил ответ в срок

#### 🔄 Дополнительные сетевые проблемы:
- `net::ERR_DNS_FAILED` - проблемы с DNS
- `net::ERR_CONNECTION_REFUSED` - отказ соединения
- `Timeout exceeded` - тайм-ауты операций
- `Connection reset` - разрыв соединения
- `Read timeout` / `Write timeout` - тайм-ауты операций ввода/вывода

## Преимущества новой системы

1. **Прозрачность**: Пользователи всегда знают, что происходит с их сессией
2. **Надежность**: Автоматическое восстановление при временных сбоях
3. **Сохранение прогресса**: Сессии не теряются при сетевых проблемах
4. **Умная классификация**: Различные стратегии для разных типов ошибок
5. **Интеграция**: Работает с системами persistent sessions и smart queue
